IA Activa, Agentes & Gobernanza

I. Arquitectura Cognitiva y Agentes Bloque 1

Análisis profundo sobre cómo los modelos evolucionan de ser sistemas de consulta estática hacia agentes capaces de razonar, planificar y ejecutar objetivos de negocio de forma autónoma.

01 IA Activa (Agentes Autónomos)
Paradigma
Definición Técnica Extensa
A diferencia de la IA Pasiva (RAG), que solo devuelve texto, la IA Activa integra un "motor de razonamiento" que le permite interactuar con el entorno. Un agente puede llamar APIs, ejecutar código, modificar bases de datos y gestionar flujos de trabajo de principio a fin para alcanzar una meta definida.
🎯 Insight del PM
Tu planificación de backlog cambia: ya no pedís "pantallas", pedís "capacidades operativas" (herramientas) que el agente usará para resolver el problema solo.
02 Loop ReAct (Reason + Act)
Arquitectura
Definición Técnica Extensa
Arquitectura que obliga al modelo a alternar entre pasos de pensamiento explícito y acciones técnicas. Se basa en tres etapas: Thought (el agente verbaliza su plan), Action (invoca una herramienta) y Observation (lee el resultado de esa herramienta para decidir el siguiente paso).
🎯 Insight del PM
Es vital para la explicabilidad. Si el agente comete un error, podés revisar el "log de pensamientos" para ver exactamente dónde se desvió su lógica.
03 Orquestador y Trabajadores
Arquitectura
Definición Técnica Extensa
Diseño multi-agente donde un "Orquestador" central descompone el pedido del usuario en subtareas y las delega a "Workers" especializados (ej. un lector de balances, un auditor de SQL). El orquestador luego ensambla todas las respuestas en un resultado final consolidado.
🎯 Insight del PM
Este patrón reduce drásticamente las alucinaciones al permitir que cada agente se enfoque en una tarea atómica y use solo las herramientas que necesita para ese paso.

II. Integración y Validación Técnica Bloque 2

04 Pydantic
Librería / Validación
Definición Técnica Extensa
Es la librería líder en Python para la **validación de datos y gestión de configuraciones** mediante el uso de anotaciones de tipo. En el contexto de IA, se usa para obligar al LLM a que su respuesta cumpla estrictamente con un esquema definido, lanzando un error si falta un campo o si el formato es incorrecto (ej. si el modelo manda un texto donde se esperaba un número).
💡
Analogía Profesional: Es el "oficial de cumplimiento" de los datos. No importa lo que el agente quiera mandar; si el documento no tiene el sello y los campos tal cual los pide el sistema, Pydantic lo rebota y le exige a la IA que lo corrija.
05 JSON Schema
Estándar / Contrato
Definición Técnica Extensa
Es un vocabulario declarativo que permite anotar y validar documentos JSON. Define la estructura, los tipos de datos y cuáles campos son obligatorios. Es el "contrato" que firmás entre el modelo de IA y tu backend para asegurar que hablen el mismo idioma técnico sin ambigüedades.
06 Tool Calling
Integración
Definición Técnica Extensa
Capacidad de un modelo para generar instrucciones estructuradas (JSON) que indican qué herramienta externa quiere usar y con qué parámetros. El modelo no "hace" la acción; emite el pedido técnico para que tu sistema la ejecute de forma segura.

III. Gobernanza, Observabilidad y Riesgo Bloque 3

07 Observabilidad (Langfuse)
Gobernanza
Definición Técnica Extensa
Herramientas especializadas (como Langfuse o Arize Phoenix) que permiten monitorear el ciclo de vida completo de una interacción con la IA. Permiten rastrear trazas de ejecución, medir costos de tokens por usuario, evaluar la latencia y, lo más importante, capturar el feedback del usuario para mejorar los prompts.
🎯 Insight del PM
Como PM, estas herramientas son tus mejores amigas. Te permiten ver los logs reales, entender dónde fallan los agentes y justificar los costos de infraestructura ante gerencia con datos duros.
08 API Gateway (Security Layer)
Seguridad
Definición Técnica Extensa
Un servidor intermedio que actúa como única puerta de entrada para las peticiones del agente de IA hacia tus sistemas críticos. Valida, filtra y audita cada solicitud, asegurando que la IA nunca toque los datos de producción de forma directa y sin supervisión técnica.
💡
Analogía: Es el cajero blindado del banco. Vos le pasás el cheque por la ranura (el Gateway), él verifica que todo esté en orden y recién ahí saca la plata de la bóveda (tu base de datos). Vos jamás entrás a la bóveda personalmente.
09 Human-in-the-loop (HITL)
Gobernanza
Definición Técnica Extensa
Mecanismo de control donde el agente pausa su ejecución y solicita aprobación humana antes de realizar una acción crítica, cara o irreversible (ej. emitir un pago o mandar un mail masivo).
10 Guardrails
Seguridad
Definición Técnica Extensa
Sistemas de filtrado (como NeMo Guardrails) que actúan como una capa exterior al modelo de IA. Bloquean inputs ofensivos del usuario o impiden que el modelo responda sobre temas que no son de su incumbencia (ej. hablar de política en un bot de atención al cliente).

IV. Optimización y Memoria Bloque 4

11 KV Cache
Costos / Latencia
Definición Técnica Extensa
Técnica que guarda en memoria GPU los cálculos de las partes del prompt que no cambian (instrucciones base). Esto reduce el "Time to First Token" (TTFT) y baja los costos de procesamiento de tokens de entrada repetitivos.
12 Gestión de Estado (Memoria)
Arquitectura
Definición Técnica Extensa
Habilidad del agente para retener contexto entre interacciones. Corto Plazo: El historial del chat actual. Largo Plazo: Información guardada en bases vectoriales que el agente puede recuperar meses después para recordar preferencias o datos históricos del usuario.
13 Reasoning Tokens
Modern LLMs
Definición Técnica Extensa
Nuevos modelos (como la familia o1 de OpenAI) que utilizan tokens internos específicos para "masticar" el problema antes de dar la respuesta final. Estos tokens no se le muestran al usuario pero se cobran, permitiendo al modelo resolver quilombos lógicos y matemáticos mucho más complejos que un LLM estándar.
14 Límites de Iteración (Max Iterations)
Costos / Seguridad
Definición Técnica Extensa
Cortafuegos lógicos que limitan cuántas veces el agente puede intentar resolver un paso antes de rendirse. Evita que el agente entre en un "bucle infinito" de llamadas a la API si no logra encontrar la solución, protegiendo así el presupuesto de nube de la empresa.
